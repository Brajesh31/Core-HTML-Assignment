# 🧱 Content Structure and Semantic Inventory

## 📌 Document skeleton

The assignment pages generally follow a standalone HTML document structure with doctype, `html lang="en"`, `head` metadata, a title, and a body. Several pages add embedded styles or inline styles.

## 🧩 Elements observed in the assignment

| Category | Elements/patterns observed | Assignments |
|---|---|---|
| Text/inline semantics | `strong`, `i`, `u`, `mark`, `sup`, `sub`, `small`, `del`, `em` | Q1, Q4 |
| Navigation/linking | `a`, `nav`, `header`, `hr` | Q2, Q3 |
| Headings and paragraphs | `h1`, `h2`, `h3`, `p` | Q2, Q3, Q6–Q8 |
| Lists | `ol`, `ul`, `li`, `dl`, `dt`, `dd` | Q4, Q5, Q6, Q7 |
| Tables | `table`, `caption`, `tr`, `th`, `td`, `rowspan`, `colspan` | Q6, Q8 |
| Layout/section examples | `div`, `article`, `footer`, `main`, `form`, `button`, `input`, `option` text/examples | Q4 |

## 💾 Content model

The repository is static content, not a data-driven application. The main units are:
- Assignment page: a standalone HTML document corresponding to a numbered question.
- Q3 mini-site page: one of three linked HTML documents.
- Screenshot artifact: a pre-existing PNG associated with a question.

No JSON content store, server database, API schema, or user-generated record model was found.
